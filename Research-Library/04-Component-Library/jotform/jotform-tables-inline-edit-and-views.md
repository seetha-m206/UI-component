## Location

Reached via the app-shell mode-switcher ("Form Builder ▾" → Tables) or directly at `jotform.com/tables/{id}`, consistent with the multi-product mode-switcher pattern documented in [[jotform-app-shell-builder]] and [[jotform-sign-builder]]. A Table auto-bound to a form opens with that form's submissions already populated as rows; "+ New Tab" inside a Table workspace is also where every other view type (Calendar, Boards, Cards, Uploads, Reports) and the AI table-creation entry point live, confirming Tables is the umbrella multi-view workspace P1 described.

## Structure

The grid view has a standard spreadsheet shell: a search bar, a Filter control, a Columns manager, a "Form ▾" button (presumably linking back to the source form), and "Download All." Each column header shows a type icon (a tag icon for Single Choice, a star for Star Rating, an @ for Email, a calendar icon for Submission Date, etc.) matching the source form field's type. Rows are numbered, each with a star/favorite toggle and a "⋮" row menu. Hovering/selecting a row's leftmost cell reveals a blue "View" badge that opens a full row-detail side panel ("1 of N Entries," with prev/next navigation, download, print, more-options, and settings icons).

## Actions

| Action | Result |
|---|---|
| Single-click a grid cell | Selects the cell (blue border); no edit affordance yet for most types |
| Click an already-selected text/choice cell again | Enters active edit mode in place |
| Click a row's Submission Date cell, then the "View" badge that appears | Opens the full row-detail panel |
| Click "+ ADD" at the bottom of the grid | Adds a new blank row |
| Click the "+" column header | Opens "Add a New Column" (BASIC / AI COLUMNS / FORMULA / BUTTONS / CONNECTION tabs) |
| Click "+ New Tab" | Opens the view-type gallery (Table, Calendar, Boards, Cards, Uploads, Reports) plus the "Create Your Table with AI" prompt box |

## Behavior & States

**1. Inline editing works, but support is genuinely inconsistent across field types — directly answering the brief's core question.** FACT, established through direct, repeated testing on each field type.

- **Short Text and Email**: fully inline-editable in the grid itself. The interaction is click-to-select, then a second click on the already-selected cell to enter an active text-edit state (a visible text caret appears); typing replaces/appends content; Tab commits the edit and advances to the next cell, Escape cancels. Confirmed both ways (edited "Iced Latte" → "Iced LatteX" → back to "Iced Latte"; confirmed an active caret in the Email cell).
- **Single Choice** (the visit-frequency field): fully inline-editable in the grid. The second click reveals the current value as a dropdown control ("Rarely ⌄"); clicking it opens a real searchable dropdown listing every choice option, color-tag-coded exactly as the grid chip itself, with the current value checked. This worked identically whether triggered from the grid cell directly or from the row-detail panel.
- **Star Rating: NOT inline-editable directly in the grid cell**, despite looking interactive. FACT — tested repeatedly. Selecting the cell reveals a small "×" clear-icon next to the stars, but clicking on any individual star position — tested at multiple precise x-coordinates, across select/click/click-again and 3-click sequences — never changed the displayed rating; no hover-preview highlight appears either. **Star Rating is editable from the row-detail "View" panel instead** — there, clicking a star does produce a hover highlight and does change the rating (confirmed by setting a 1-star entry to 4 stars and back to 1 star, each change visibly reflected immediately). This makes Star Rating a "panel-only edit" field type, not a flatly read-only one.
- **Submission Date**: clicking the cell in the grid does not produce any visible edit affordance (no border, no caret) — appears grid-read-only. In the row-detail panel, clicking the date value does turn it into a highlighted, input-like box, but this was not verified to actually persist a changed value — flagged as an open question, not a confirmed finding.

**2. Non-Table views genuinely reflow the same underlying submission data — not separate content — confirmed on two view types.** FACT, directly answering brief item 2.

- **Calendar view**: creating one prompts a choice between "Start from Scratch" and "Connect to Form" (pulling in an existing form's submissions). Connecting to the Coffee Shop Feedback Form and mapping "Submission Date" as the Start Date field produced a full month-grid calendar (plus a companion "Events" list tab) with all three submissions appearing as individual events on Oct 5 — the actual submission date — auto-titled by the first substantive text answer (the favorite-drink value: "Cappuccino," "Espresso," "Iced Latte"). This is unambiguously the same three rows from the grid, reflowed onto a calendar axis — not a separate or sample dataset.
- **Boards (kanban) view**: creating one offers a "Manage task groups" dropdown with two modes — "Custom" (manually-defined, generic Backlog/Waiting/In Progress/Done-style columns) or **"From a field"**, which lists the form's own choice-type fields and auto-generates one kanban column per actual answer option, matching the field's own color-coding. A second setup step lets you pick which field supplies the card title and toggle per-field visibility on the card body, with a live card preview. The finished board genuinely grouped all three real submissions into their correct columns, each card showing the submission's favorite drink, its grouping-field tag, and its star rating rendered as actual stars — again, the same three rows, not placeholder content.
- Cards, Uploads, and Reports view types were seen in the gallery (confirmed to exist, per P1) but not tested this pass.

**3. AI Columns and Formula tabs both genuinely compute — neither is placeholder UI.** FACT, directly answering brief item 3, confirmed via actual column creation and result inspection, not just the preview control.

- The **AI COLUMNS** tab (marked "NEW") offers six types: Summarize, Calculate, Categorize, Translate, Sentiment Analysis, Custom AI Column. Testing Calculate: given the prompt "[Quantity in Stock] minus [Reorder Level]" (built using the dialog's own "+ Insert Column" token-picker, which binds live column references), the created column showed correct, row-specific arithmetic for all 5 rows of a freshly AI-generated inventory table: 42−10=32, 125−25=100, 18−5=13, 67−15=52, and critically 9−12=**−3** (a correctly signed negative result, not clamped to zero) — strong evidence this is real per-row computation, not a canned/templated response. The column also offers an "Automatically include new submissions" toggle (on by default), meaning it's wired to recompute for future rows, not a one-time snapshot.
- The **FORMULA** tab offers four types: Advanced Formula, Rollup, Lookup, Counter. Testing Advanced Formula: a genuine token-based spreadsheet-style formula builder — click Column chips and Function/Operator chips (Concatenate, Comma, Plus, Minus, Divide, Multiply, UPPER, LOWER, LEN, LEFT, and more below the fold) to assemble an expression visually, no free-text formula syntax required. Building `[Quantity in Stock] − [Reorder Level]` produced a new column with results identical to the AI Calculate column above (32.00, 100.00, 13.00, 52.00, −3.00 — shown with two decimal places, unlike the AI column's integer display), confirming this is a second, independently-correct computation path.
- Minor UI friction note: the "Generate Preview" button inside the AI Columns' Calculate step appeared visually inert/unresponsive to repeated clicks regardless of prompt content during this pass; actually clicking through to "Create Column" worked reliably and computed correctly every time.

**4. "Create Your Table with AI" genuinely builds a real, correctly-structured, populated table from a natural-language prompt.** FACT, directly answering brief item 4. The prompt "Create a simple inventory tracker table for a coffee shop with item name, category, quantity in stock, and reorder level" produced, within roughly 8–10 seconds, a new Table tab named "Coffee Shop Inventory" with exactly four columns matching every field named in the prompt, correctly typed (Item Name/Category as text, Quantity in Stock/Reorder Level as Number), plus 5 auto-generated sample rows with plausible retail-inventory data. One nuance worth flagging: the sample data, while well-formed, leaned generic-office/retail rather than tightly coffee-shop-themed — "Wireless Mouse," "Notebook," "LED Desk Lamp," and "USB-C Cable" sit alongside the one genuinely on-theme row, "Ceramic Coffee Mug." The column structure honored the prompt precisely; the sample content only partially did.

## Rules & Validation

- The "Automatically include new submissions" toggle on an AI Calculate column (on by default) is the closest thing to a formalized rule observed — it governs whether the computed column keeps itself current as new rows are added, rather than being a one-off snapshot.
- Star Rating's grid-cell non-editability functions as an implicit rule (edits there are silently no-ops), though nothing in the UI explicitly states this — a user clicking stars directly in the grid gets no feedback that nothing happened, which is a minor discoverability gap worth flagging.

## Technical Data

- Row-detail panel URL/state wasn't inspected at the network level this pass — edits were confirmed purely through UI state (value changes, Tab-driven cell advancement, panel open/close).
- The AI-generated "Coffee Shop Inventory" table and both the AI Calculate and Advanced Formula columns were created on the same underlying Tables data model used for the form-bound "Coffee Shop Feedback Form" table — confirmed only by UI consistency (identical grid chrome, identical Add Column dialog), not independently verified via API inspection.

## Best Observed Approach

**For "how are results reviewed" overall**, no single product in this five-way comparison wins across every dimension — each has a genuine, confirmed strength no sibling matches:
- **Zoho Forms** has the strongest confirmed list-level filtering (datatype-aware operators, client-side pre-validation).
- **Typeform** has the strongest confirmed charting technology (real SVG via visx, computed scales/axes) for the dimensions it covers, though it offers no alternate view mode at all.
- **Paperform** has a uniquely first-class Partial/abandoned-submissions surface no sibling has an equivalent for.
- **Google Forms** has a uniquely direct inline-grading workflow (per-question points override + private feedback) tied to its quiz-first design.
- **JotForm**, confirmed this pass, has two genuine firsts in this comparison set: (1) **working inline cell editing directly in the raw grid** for several field types — no sibling product documents editing a respondent's own answer value directly in a list cell, only via a separate edit modal (Zoho) or not at all (the rest); and (2) **two independently-functional computed-column paths** (AI-driven and formula-driven) layered directly on top of response data — no sibling product has a documented equivalent to either. RECOMMENDATION: JotForm's "from a field" auto-column-generation in Boards view (deriving kanban columns directly from a choice field's actual answer options, color-matched to the field's own chip colors) is also a strong, low-friction pattern — it turns an existing form field directly into a working board with zero manual setup beyond picking the field, a lower-friction setup than Zoho's own manual grouping-field selection in its (reliability-unconfirmed) Kanban view.

Set against these strengths: JotForm's own inline-editing story is **not uniformly good** — Star Rating's silent grid-cell no-op (no error, no visual feedback, it simply does nothing) is a real discoverability gap that none of the sibling products' simpler, more consistent (if less capable) surfaces would produce, since they don't offer inline editing to be inconsistent about in the first place.
