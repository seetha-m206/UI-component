- Provider state was not created, edited, imported, deleted, sent, connected, or configured.
- Canonical records distinguish `OBSERVED`, `RECONSTRUCTION`, and `NEEDS VERIFICATION` evidence.
- Local previews use fictional people, companies, addresses, values, and messages.
- Authenticated screenshots are not retained in the public catalogue because they exposed account context and sample contact details.
- The provider explicitly labelled the dashboard surface as a sample image. Its displayed metrics are not treated as account performance data.

- Import file selection, field mapping, import execution, role changes, user assignment, license changes, scoring changes, Freddy toggles, AI prompts, and paid actions were not exercised.
- The independent-component expansion adds 17 atomic patterns for boards, cards, loading, menus, drawers, toolbars, record actions, fields, activities, import controls, licensing, roles, permissions, scoring and Freddy configuration.
- Six additional screen-level fixtures preserve observed loading states for the application shell, Analytics, Workflows, Deals, contact activity and deal detail.
- The 2026-10-08 deep audit covers 30 safely accessible workflows and registers eight independently addressable levels for each: screen, action, atomic, state, loading, empty, error and interaction.
- This adds 240 evidence-aware component records and 480 local fixture states. Provider-observed levels are labelled `OBSERVED`; absent loading, empty, error or interaction states remain explicit `RECONSTRUCTION` records.
- The audit receipt contains 46 browser evidence points: 40 structured captures plus six additional verified states for settings search, workflow templates, conversation automation, call workflows, deal import and the required-fields popover.
- Network evidence is sanitized to method, normalized path, status, request shape, response shape and triggering action. Tenant identifiers, record identifiers, personal data, credentials and volatile values are excluded.
- A repository-local vector index now contains one deterministic 64-dimensional signed feature-hash embedding for every Freshsales record. It is an offline catalogue aid, not a model embedding and not a write to LanceDB or Qdrant.
- No user-facing provider error screen was naturally observed. Runtime console warnings and errors are recorded separately and are not presented as provider error components.
