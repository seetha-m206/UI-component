# Reconstructed preview: JotForm Tables — inline editing, computed columns, and non-Table views

Source record: `Research-Library/04-Component-Library/jotform/jotform-tables-inline-edit-and-views.md` (JF7, 2026-10-05).

## Evidence priority

Reproduced faithfully from direct, repeated live testing against real submission data (Coffee Shop Feedback Form, 3 genuine test responses):

- **Short Text and Email cells are fully inline-editable in the grid**: click to select (blue border), click the already-selected cell again to enter an active edit state, type, and Tab/blur commits the value. This preview reproduces click-to-select → click-again-to-edit exactly, rather than collapsing it to a single click (which the real product does not do).
- **Single Choice cells reveal a real dropdown on the second click**, pre-set to the current value, listing every answer option — reproduced here as a native `<select>` populated with the field's actual options (`Rarely` / `Weekly` / `Daily`), matching the confirmed real behavior that this worked identically from the grid cell or the row-detail panel.
- **Star Rating is a confirmed, deliberately-reproduced non-op in the grid cell.** The source record states this was tested repeatedly — "tested at multiple precise x-coordinates, across select/click/click-again and 3-click sequences — never changed the displayed rating; no hover-preview highlight appears either." This preview reproduces that exactly: the entire grid cell (stars included) is a single click target that only ever toggles cell *selection*; it never enters an edit state and clicking never changes the stored rating. This is **not a bug in this preview** — it is the real product's own confirmed defect, faithfully kept rather than "fixed." The `JotformTablesInlineEditAndViews.test.tsx` suite has a dedicated test asserting this no-op.
- **Star Rating IS editable from the row-detail "View" panel**, with a genuine hover-preview highlight and an immediate, visible rating change — confirmed by the source record setting a 1-star entry to 4 stars and back. Reproduced here as real `<button>` stars with `onMouseEnter`/`onFocus` hover-preview state, operating on the *same* row state the grid reads from (clicking a star in the panel updates the grid cell underneath it, provable in the preview by closing the panel and re-reading the grid cell's label).
- **Submission Date is grid-read-only** — clicking the cell only selects it; no edit affordance (input, caret, dropdown) ever appears, matching the confirmed "appears grid-read-only" finding.
- **Calendar and Boards views reflow the exact same row state, not separate sample data.** Both views are derived directly from the same `rows` state array the Table view edits — there is no second data source. Boards groups cards by `visitFrequency` into one column per confirmed real answer option (`Rarely` / `Weekly` / `Daily`), matching the source's confirmed "auto-generates one kanban column per actual answer option" ("from a field") finding, rather than requiring manual column setup.
- **The row-detail panel's "1 of N Entries" label and prev/next navigation** are reproduced from the confirmed real panel chrome.

## Deliberate scope reductions

- **The "View" badge is a persistently visible button, not a hover-reveal-only affordance.** The source record describes it appearing on hover/selection of a row's leftmost cell. A hover-only trigger with no persistent, keyboard-reachable equivalent would fail this codebase's "keyboard operable" requirement, so this preview makes the same control always visible and always focusable — a reasonable accessibility-motivated simplification, not a behavioral embellishment (the panel's own content and interactions are reproduced as-tested).
- **The Star Rating grid cell's "×" clear icon is rendered only when the cell is selected, for visual fidelity, but is not wired to any click handler.** The source record mentions the icon appears but does not describe or confirm what clicking it does; rather than invent a "clear rating" behavior that was never tested, this preview shows the icon decoratively and leaves it non-interactive.
- **The computed-column demo is a single combined "+ Add Computed Column" button, not the full dual-path AI Columns / Formula UI.** The source record's standout finding is that JotForm has *two independently correct* computation paths over response data (a natural-language "AI Columns → Calculate" tab and a token-based "Formula → Advanced Formula" builder) which, when both built with the same `[Quantity in Stock] − [Reorder Level]` expression, produced matching correct results (32, 100, 13, 52, −3) on the AI-generated inventory table. Reconstructing both dialog flows (six AI Column types, four Formula types, a token-picker UI, an "Automatically include new submissions" toggle) was out of scope for a self-contained preview. This preview instead reproduces the *end result* both paths converge on: a single button that appends one computed column performing the same per-row subtraction (`quantity − reorderLevel`) confirmed against the first three of the source record's own tested rows (42−10=32, 125−25=100, 18−5=13), proving the arithmetic is genuinely per-row rather than a static display. The dual-path distinction (AI vs. Formula) itself is **not** demonstrated interactively here — only documented in this README, per the task's own stated fallback ("a simplified single combined demo is fine if full dual-path is too much scope").
- **Submission Date's panel editability is intentionally not reproduced as editable.** The source record explicitly flags this as unconfirmed ("not verified to actually persist a changed value") — this preview keeps Submission Date fully read-only in both the grid and the panel, rather than guessing at untested persistence behavior.
- **Cards, Uploads, and Reports view types are not included.** The source record confirms they exist in the "+ New Tab" gallery but were not tested this pass — nothing to faithfully reconstruct.
- **Boards view is read-only (no drag-to-regroup).** The source record itself flags that JotForm's Boards view "was not stress-tested with an actual drag gesture" this pass — cards were populated via the grouping-field configuration, not manual drag. This preview matches that: Boards is a pure, config-driven reflow of the same row data, with no drag interaction implied or built.
- **Row/column add-and-remove ("+ ADD" row, "+" column header's full BASIC/AI COLUMNS/FORMULA/BUTTONS/CONNECTION dialog) are not implemented.** They are confirmed to exist structurally but weren't the point of this preview's brief (inline editing, grid-vs-panel Star Rating defect, and view reflows); adding them would have widened scope well past the documented findings being reconstructed.
- Following this codebase's established precedent (`jotform-input-table-field`, `entries-kanban-view`): this component is **not** `value`/`onChange`-shaped — it owns all grid/view/panel state internally via `useState`, so the hosted preview panel is genuinely interactive without a dedicated controlled wrapper.
