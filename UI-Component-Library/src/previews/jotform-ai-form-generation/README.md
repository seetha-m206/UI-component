# Reconstructed preview: JotForm AI Form Generation (Describe your form + Form Copilot)

Source record: `Research-Library/04-Component-Library/jotform/jotform-ai-form-generation.md` (JF5, 2026-10-05).

## Evidence priority

Reproduced faithfully from the source record's live-tested findings:

- **"Describe your form" generates directly into the builder, with no staging/review step.** Submitting the prompt goes straight to a populated form (title, fields, relabeled submit button) — this preview does the same; there is no intermediate approval screen anywhere in the flow.
- **The pre-creation prompt and all post-creation in-builder edits are literally the same conversation.** The initial generation turn appears as the first message in the Form Copilot's own chat history, complete with its own Undo link — reproduced here by writing the generation turn into the same `turns` array that all later Copilot edits append to, not a separate system.
- **Free-text Form Copilot prompts apply immediately**, with a live on-canvas toast ("✦ Adding '\<Field Name\>'…") and a chat reply carrying its own "↺ Undo" link — reproduced exactly, including the record's verbatim tested copy for the "add an email field" case ("I've added an email address field to the form so you can collect replies for follow-up.").
- **"Suggest new questions" behaves differently from a free-text prompt — it does not apply directly.** Clicking it opens a checklist of proposed questions with checkboxes and a separate "Add question →" button that stays disabled until at least one box is checked. Confirming triggers a second turn (grayed-out checklist + a "• • • Thinking" indicator) that applies only the checked items, using the same toast + chat-reply + Undo pattern as a free-text edit. This "mixed immediacy" (free text = immediate, this one chip = review-first) is the record's most load-bearing behavioral finding and is reproduced as the one structural difference in this preview's two apply paths.
- **Per-turn Undo is real, not decorative.** Clicking "↺ Undo" on any turn that added fields removes exactly those fields from the live form and disables that turn's own Undo link (showing "Undone"), leaving every other turn's Undo independently clickable. Undoing the generation turn reverts all the way back to the "Describe your form" intro screen, since that turn is what created the form in the first place.
- **Form Copilot panel chrome**: header reading "Form Copilot AI — Jotform Form Specialist" with a mascot glyph and a collapse/expand control, a scrollable chat thread, and a composer with a "+" Suggestions menu and a text input — matches the record's described structure (the close "×" control and the "Draw & Edit" / "Talk" voice buttons are omitted; see Scope reductions).

## Deliberate scope reductions

- **No real AI call.** This is a reconstruction, not a live model integration. The initial "generation" and every Copilot edit are produced by small, hardcoded/keyword-matched canned responses (see `generateDemoForm()` and `resolveCopilotEdit()` in `JotformAiFormGeneration.tsx`), not an actual language model. The generated demo form content (title, three fields, relabeled submit button) matches the exact output the source record confirmed live for its one tested prompt; any prompt text submitted in this preview produces that same canonical output rather than genuinely varying by input — faithfully reproducing confirmed behavior, not simulating general-purpose generation.
- **Only the "email address" Copilot edit reproduces the record's verbatim tested chat copy.** Other keyword branches (phone, name, rating/star, and a generic fallback) are reasonable extrapolations added so the demo doesn't feel like a one-trick fixture, but they are not independently confirmed against the real product and should not be read as documented JotForm copy.
- **Only "Suggest new questions" is wired among the "+" Suggestions chips**, matching the record's own statement that only this one chip was tested. The other chips mentioned in the record ("Create conditions," "Customize form design," etc.) render as visibly disabled, non-interactive list items in the Suggestions menu rather than being omitted entirely or guessed at — their actual apply-immediately-vs-review-first behavior is unconfirmed, so this preview deliberately does not invent it.
- **The suggested-questions list is a fixed canned set of five items** (three shown by default, two more behind "Show more ⌄"), matching the record's observed example questions. It is not a real per-prompt AI suggestion generator.
- **Star Rating field is a simple 1–5 clickable button row**, not JotForm's actual Star Rating field implementation — sufficient to demonstrate "a genuine 5-star field, not a generic substitute" per the record's finding, without reconstructing JotForm's full Star Rating component (a separate, not-yet-documented component in its own right).
- **Close ("×") control, "Draw & Edit" toggle, and the "Talk" voice button are omitted** from the Form Copilot panel chrome. The record describes their presence but does not document any tested behavior for them, so adding interactive stand-ins would be inventing behavior rather than reproducing it.
- **Generation and "Thinking" delays are compressed** (hundreds of milliseconds here vs. the record's observed ~3–6s generation and ~4s suggestion-confirm turnaround) purely so the preview stays comfortably testable and demo-friendly; the presence of a brief transitional loading state before the result appears is reproduced, its exact real-world duration is not.
- **Not `value`/`onChange`-controlled.** Following this codebase's established precedent (`jotform-input-table-field`, `entries-kanban-view`): the whole chat thread, generated-form state, and per-turn undo history are owned by internal `useState`, so the generic `ReconstructedPreviewPanel` harness doesn't need to auto-wire any external prop — there is no single value-shaped prop this component could sensibly expose.
